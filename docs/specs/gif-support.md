# GIF 格式支持

> 术语以仓库根 `CONTEXT.md` 词汇表为准:动画资产、时序、Keep-if-smaller、转换豁免、有损吸附、尺寸压缩。
> 历史包袱:此前数版失败,死因已确认为 (A) ImageIO GIF 编码器产物必然偏大 → keep-if-smaller 下永远"未变化";(B) 只取首帧的路径静默销毁动画;(D) 全帧驻留内存导致大 GIF 内存爆炸。本 spec 的每条决策都针对性封死这三条死路。

## Problem Statement

我批量拖入图片做压缩时,GIF 文件实际上得不到任何压缩——结果总显示"未变化";更糟的是,选了 PNG/JPEG 输出格式时,动画 GIF 会被拍扁成静态首帧且原件被删,动画内容不可逆丢失。大尺寸 GIF 还曾把 app 内存撑爆。我需要 GIF 和其他格式一样:体积实打实变小、能按我选的最大宽度缩放,并且压缩成品的逐帧延迟、循环行为和动画内容与原件完全一致。

## Solution

GIF 进 GIF 出、原地替换,沿用 keep-if-smaller 语义。app 内置一个自研 GIF 编码引擎(与 PNG 引擎同哲学:纯 Swift、零外部进程、零 GPL 依赖):系统 ImageIO 只负责解码(帧、逐帧延迟、循环次数),编码由全局调色板量化 + 帧间差分 + 透明像素复用 + 自写 LZW 完成。质量滑杆通过"调色板颜色数 + 有损吸附"双杠杆控制压缩强度,任何档位都不触碰时序。处理管线为二遍流式,内存峰值恒定在少数几帧画布,与 GIF 总帧数无关。动画资产享受转换豁免:即使用户选了 PNG/JPEG 输出,动画 GIF 仍走 GIF→GIF 压缩,只有静态单帧 GIF 参与格式转换。

## User Stories

1. As a 批量压缩用户, I want 拖入的 GIF 与 JPEG/PNG 一样被实际压小, so that 我不再看到 GIF 全部显示"未变化"。
2. As a 批量压缩用户, I want GIF 压缩后仍是 GIF 并原地替换原件, so that 我的文件路径、链接和工作流不因扩展名变化而断裂。
3. As a 表情包收藏者, I want 压缩后的 GIF 帧数与原件完全一致, so that 动画内容一帧不丢。
4. As a 表情包收藏者, I want 压缩后每一帧的延迟与原件逐帧相等, so that 动画节奏不变快、不变慢、不卡顿。
5. As a 表情包收藏者, I want 循环次数(无限循环/固定次数)原样保留, so that 循环行为与原件一致。
6. As a 透明贴纸用户, I want 透明背景在压缩后依然透明, so that 贴纸叠在聊天背景上不出现黑底或白底。
7. As a 屏录分享者, I want 用质量滑杆换取更小体积, so that 大屏录 GIF 能塞进论坛或 IM 的体积上限。
8. As a 屏录分享者, I want 滑杆调低时体积显著下降(颜色数减少 + 有损吸附), so that 我可以自己权衡画质与体积。
9. As a 屏录分享者, I want 滑杆调到最高时接近无损(原调色板已 ≤256 色时不引入色偏), so that 高质量档不糟蹋原图。
10. As a 尺寸敏感用户, I want 给 GIF 设定最大宽度后所有帧统一等比缩小, so that 输出画布尺寸符合我的要求且各帧对齐不错位。
11. As a 尺寸敏感用户, I want 缩放永不放大(原宽小于设定值时保持原尺寸), so that 小图不被无意义地插值变糊。
12. As a 尺寸敏感用户, I want 缩放后的 GIF 时序仍与原件逐帧相等, so that 改尺寸不改播放行为。
13. As a 混合文件夹批量用户, I want 选择 PNG/JPEG 输出时动画 GIF 自动豁免转换并按 GIF 压缩, so that 我的动图不会被拍扁成静态图后连原件一起消失。
14. As a 混合文件夹批量用户, I want 静态单帧 GIF 照常转换为我选择的 PNG/JPEG, so that "统一输出格式"的意图对非动画文件依然生效。
15. As a 大文件用户, I want 处理超大 GIF(高分辨率 × 数百帧)时内存占用恒定, so that app 不再因一个屏录怪物而内存爆炸或被系统杀死。
16. As a 谨慎用户, I want 只有当结果严格更小时才替换原件、否则显示"未变化", so that 已被深度优化过的 GIF 永远不会被改坏或变大。
17. As a 谨慎用户, I want 处理中途任何失败都不触碰原件, so that 断电、报错、磁盘满都不会留下半截文件。
18. As a 隐私敏感用户, I want GIF 压缩顺带剥离注释等元数据块, so that 与 JPEG/PNG 路径一致地不泄露出处信息。
19. As a 动画质量敏感用户, I want 抖动噪点在帧间保持稳定(有序抖动), so that 播放时不出现全画面"蚂蚁爬"闪烁。
20. As a 历史面板用户, I want GIF 压缩结果(原大小/新大小/降幅)与其他格式一样记录在历史里, so that 我能核对每个文件的压缩效果。
21. As a 离线用户, I want GIF 引擎完全内置于 app, so that 无网络、无外部命令行工具也能压缩。

## Implementation Decisions

- **引擎自研,解码/编码分离**:ImageIO 仅用于解码(帧位图、逐帧延迟、循环次数的读取已验证可靠);编码完全自研——ImageIO 的 GIF 编码路径彻底废弃,不再作为任何候选。gifsicle(GPLv2)与 libimagequant 一样被授权立场排除,不进链接。此决策满足 ADR 三条件,实施时应同步落一篇 ADR。
- **管线形态:二遍流式**。第一遍逐帧解码只累积全局颜色直方图(可按固定步长抽样以摊薄 CPU),第二遍逐帧解码 → 缩放 → 有损吸附 → 量化映射 → 帧间差分 → LZW 写出,帧位图即行释放。常驻内存 = 上一帧合成画布 + 当前帧,与总帧数无关。全帧驻留数组属于被封死的死路 (D),任何实现不得引入。
- **调色板:全局单调色板**,由第一遍直方图经中位切分类量化得出(思路与既有 PNG 量化器同源)。颜色数上限随质量滑杆:滑杆 × 256,下限 16。
- **质量滑杆双杠杆**:① 调色板颜色数;② 有损吸附——像素与上一帧同位置像素(或量化后邻近值)的差异在阈值内时吸附过去,阈值随滑杆降低而放宽,以延长 LZW 匹配串。两个杠杆都只作用于像素颜色;时序数据在任何档位原样透传。
- **帧间差分**:维护上一帧合成画布,当前帧与其逐像素比较,未变化区域以透明像素复用表达,只编码变化矩形。输出帧的处置方式与透明索引由编码器自主选定,不承诺与原件的内部编码方式一致——承诺的是解码后的视觉结果与时序一致。
- **抖动:Bayer 有序抖动**,噪点位置仅由像素坐标决定,帧间稳定。Floyd–Steinberg 明确排除(帧间噪点重排导致闪烁并撑大差分)。
- **尺寸压缩**:最大宽度作用于整个画布,超宽则全帧统一等比缩小,永不放大;缩放发生在合成后的完整画布上,与帧差分的重新推导衔接。
- **转换豁免**:格式转换入口先判帧数——帧数 > 1 的 GIF 为动画资产,豁免转换,改走 GIF→GIF 压缩;帧数 = 1 的静态 GIF 照常转换。
- **Keep-if-smaller 与原子替换**:沿用现有语义——临时目录内产出候选,严格更小才在原卷上原子换入;任何失败路径原件零接触。
- **循环次数与逐帧延迟**:从源逐帧读出、原样写入;延迟不做任何归一化或钳制。
- **元数据**:注释块等源元数据一律不透传,与其他格式的剥离立场一致;循环次数所在的应用扩展块除外。
- **UI 零改动**:GIF 已在支持的扩展名列表中,质量滑杆与最大宽度设置自然生效,历史面板无需新字段。

## Testing Decisions

- **单一测试缝**:全部验收断言打在现有的最高缝——压缩入口(文件进、文件出)上,以样本 GIF 文件驱动,只断言用户可观察行为(输出文件的可解码性、帧数、逐帧延迟、循环次数、透明性、尺寸、字节数、原件是否被替换)。不为编码器内部再开公开测试缝;编码器内部重构不得破坏任何测试。
- **样本矩阵**:未优化的典型多帧 GIF(测试内手工写出全幅帧 GIF89a——256 色全局表、8 位码、无帧间优化,保证臃肿;不可经 ImageIO 编码合成:现代 ImageIO 已做帧间差分优化,产物接近无损下限,"天然臃肿"前提失效)、透明背景多帧 GIF(合成)、已深度优化的顽固 GIF(入库小体积二进制夹具)、静态单帧 GIF(转换豁免的对照组)。
- **不变量断言(任何滑杆/宽度设置下)**:帧数不变;逐帧延迟逐一相等;循环次数不变;透明样本输出仍含透明;输出可被系统解码;仅严格更小才替换,"未变化"合法。
- **压缩效果断言**:未优化样本在默认档位降幅 ≥ 20%(阈值保守,防脆);顽固样本允许"未变化",但禁止变大、禁止损坏。
- **尺寸断言**:设定最大宽度后输出画布宽 = min(原宽, 设定值),全帧一致,时序不变量同时成立。
- **豁免断言**:动画样本 + PNG 输出设置 → 产物仍为 GIF 且动画完整;静态单帧样本 + PNG 输出设置 → 产物为 PNG。
- **先例**:仓库既有测试以合成像素数据驱动、断言解码回读结果(PNG 量化器测试即此风格);本 spec 沿用同风格但上移到压缩入口层。

## Out of Scope

- APNG / 视频格式的输出或互转(动画 WebP 已在后续实现中采用本 spec 的同一组动画不变量)。
- 任何 UI 变更(新滑杆、GIF 专属设置、进度细化)。
- GIF 局部(逐帧)调色板的极限优化——全局调色板 + keep-if-smaller 已保证不产生劣化结果。
- 对损坏/畸形 GIF 的修复;解码失败按现有错误路径处理。
- 交错(interlaced)GIF 输出。

## Further Notes

- 授权红线是本 spec 的隐形约束:任何 GPL/LGPL 编码器(gifsicle、giflib 的部分衍生物)不得进入链接,`THIRD_PARTY_NOTICES` 的立场延续。
- ADR《GIF 编码器自研,拒绝 ImageIO 编码与 GPL 工具链》建议随实现首个提交一并落盘(编号顺延仓库现状)。
- 有损吸附与有序抖动的参数曲线(阈值随滑杆的映射)留给实现调优,验收只锁"默认档位降幅 ≥ 20%"与全部不变量。
